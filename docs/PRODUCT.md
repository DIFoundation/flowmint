# FlowMint Product Specification

**Status:** Active | **Version:** 1.0 | **Primary track:** Real World Adoption

## Product thesis
FlowMint is a Celo-native, mobile-first application for **autonomous economic execution**: a person expresses a real economic intent; FlowMint's agent evaluates it within explicit rules and authorization boundaries; the appropriate stablecoin payment is executed; and the real-world outcome is recorded.

The agent is not the product by itself. The product is the economic workflow and its successful real-world outcome.

## FlowMint is
- Real-world payment/economic execution.
- Agent-assisted, not chatbot-first.
- Celo mainnet native.
- Stablecoin-first.
- MiniPay/mobile-first.
- Designed for genuine independent users and repeat use.
- Built around observable economic outcomes.

## FlowMint is NOT
- A generic AI chatbot.
- An agent directory.
- An Aigora-style service marketplace.
- A prompt-to-agent wrapper with no economic consequence.
- A generic wallet with an AI label.
- A synthetic transaction-volume generator.
- A collection of unrelated Celo features.

## Canonical workflow
1. User expresses/selects a real economic intent.
2. FlowMint identifies the intended action, recipient and payment parameters.
3. The agent evaluates whether the request is permitted.
4. Rules, limits, identity/context and required verification are checked.
5. The agent prepares the payment.
6. The user authorizes according to the risk level/policy.
7. FlowMint settles using a supported Celo stablecoin rail.
8. The recipient receives value.
9. The outcome is recorded and shown clearly.
10. Successful repeat use creates genuine adoption evidence.

## Principles
- **Economic outcome first:** every major feature improves a real economic workflow.
- **Agent second, not agent theatre:** autonomy must provide genuine value.
- **Human control:** users retain wallet control; agent authority is bounded.
- **Celo-native:** use Celo primitives when they materially improve the product.
- **Mobile-first:** MiniPay and ordinary mobile users are first-class.
- **Real users over vanity metrics:** never farm volume/users.
- **Minimal surface area:** build the smallest coherent product that proves the thesis.

## Success definition
We can demonstrate a clear problem, repeatable workflow, meaningful agent contribution, real Celo mainnet stablecoin settlement, independent parties receiving value, genuine users, a usable MiniPay/mobile experience, attribution-tagged activity, and evidence that the product works without synthetic volume.

## Scope rule
A feature needs answers to: (1) what real user problem does it solve, (2) which M1-M8 milestone requires it, and (3) what measurable evidence will it create. Otherwise park it in `DECISIONS.md`.
